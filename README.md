# سامانه رزرو آنلاین جلسات مشاوره

وب‌اپلیکیشن کامل رزرو وقت مشاوره با تقویم شمسی، ورود با کد یک‌بارمصرف (OTP)، پنل مدیریت، مدیریت قفل و تعطیلی روزها و ساعت‌ها، گزارش‌های آماری و خروجی Excel. رابط کاربری کاملاً فارسی و راست‌به‌چپ است و تمام زمان‌ها با منطقه زمانی `Asia/Tehran` پردازش می‌شوند.

## ۱. اجرای سریع روی ویندوز (بدون Docker)

پیش‌نیاز: فقط **Node.js نسخه ۲۲ یا بالاتر**. نصب PostgreSQL لازم نیست؛ پروژه یک PostgreSQL واقعی (نسخه ۱۷) را از داخل `node_modules` اجرا می‌کند.

```powershell
# یک بار
npm install
copy .env.example .env      # سپس AUTH_SECRET را با یک رشته تصادفی بلند عوض کنید
```

**ترمینال اول** — پایگاه داده (باید باز بماند):

```powershell
npm run db
```

**ترمینال دوم** — آماده‌سازی و اجرای برنامه:

```powershell
npm run setup        # اعمال migrationها + ساخت حساب مدیر و تنظیمات پیش‌فرض
npm run db:demo      # (اختیاری) چند کاربر، رزرو و قفل نمونه
npm run dev
```

حالا آدرس <http://localhost:3000> را باز کنید.

| بخش | آدرس | ورود |
|---|---|---|
| کاربر | `http://localhost:3000` | ثبت‌نام با هر شماره موبایل؛ در محیط توسعه **کد تأیید روی صفحه نمایش داده می‌شود** (و در ترمینال چاپ می‌شود) |
| مدیر | `http://localhost:3000/admin/login` | نام کاربری `admin` و رمز `Admin@12345` (از فایل `.env`) |

> کاربران نمونه‌ی `db:demo`: شماره‌های `09123456789` (علی محمدی)، `09123456788` و `09123456787`. شماره `09123456786` عمداً غیرفعال است.

داده‌های پایگاه داده در پوشه `.data/postgres` ذخیره می‌شوند و با بستن و اجرای مجدد `npm run db` باقی می‌مانند.

## ۲. اجرا با Docker

### نصب Docker در ایران

1. **Docker Desktop** را نصب کنید (به WSL2 نیاز دارد).
2. چون Docker Hub آی‌پی‌های ایران را مسدود کرده است، یک **mirror** تنظیم کنید:
   Docker Desktop ← Settings ← Docker Engine، و این بخش را به JSON اضافه کنید:

   ```json
   { "registry-mirrors": ["https://docker.arvancloud.ir"] }
   ```

   سپس Apply & Restart. اگر mirror کار نکرد، می‌توانید پیشوند آن را مستقیم به نام imageها بدهید:
   `set REGISTRY=docker.arvancloud.ir/` (در PowerShell: `$env:REGISTRY="docker.arvancloud.ir/"`).

### حالت آزمایشی (برای یادگیری و امتحان روی سیستم خودتان)

```powershell
docker compose -f docker-compose.dev.yml up --build
```

این دستور دو سرویس بالا می‌آورد: `db` (PostgreSQL 17) و `app` (برنامه در حالت توسعه با داده نمونه و کد OTP روی صفحه). آدرس: <http://localhost:3000>.
توقف: `Ctrl+C`. حذف کامل داده‌ها: `docker compose -f docker-compose.dev.yml down -v`.

### حالت Production

```powershell
copy .env.docker.example .env.docker   # همه مقادیر CHANGE-ME را عوض کنید
docker compose --env-file .env.docker up -d --build
```

سرویس‌ها:

| سرویس | کار |
|---|---|
| `db` | PostgreSQL 17 با encoding UTF-8، داده در volume به نام `pgdata` |
| `migrate` | کار یک‌باره: `prisma migrate deploy` و ساخت حساب مدیر؛ پس از اتمام خارج می‌شود |
| `app` | image سبک production (خروجی standalone نکست) که بعد از موفقیت `migrate` اجرا می‌شود و healthcheck دارد |

مراحل `Dockerfile` (multi-stage): `deps` (نصب پکیج‌ها) ← `builder` (ساخت) ← `migrator` / `dev` / `runner` (image نهایی، اجرا با کاربر غیر root).

> در حالت production پیامک واقعی لازم است (`SMS_PROVIDER=kavenegar` و `KAVENEGAR_API_KEY`). ورود آزمایشی (نمایش کد روی صفحه) در production **عمداً غیرفعال** است.

دستورهای مفید برای یادگیری:

```powershell
docker compose ps                       # وضعیت سرویس‌ها
docker compose logs -f app              # لاگ برنامه
docker compose exec db psql -U booking  # ورود به پایگاه داده
docker compose down                     # توقف (داده‌ها حفظ می‌شوند)
```

## ۴. امکانات

**کاربر**
- ثبت‌نام (نام، موبایل، جنسیت؛ تاریخ و ساعت ثبت‌نام خودکار) و ورود با OTP
- تقویم ماهانه شمسی؛ روزهای بسته با «بسته است»، روزهای دارای قفل ساعتی با نشانه بنفش، رزروهای خودتان با نشانه سبز
- ۲۴ بازه یک‌ساعته در روز با وضعیت‌های متمایز: قابل رزرو، رزرو شما، رزرو شده، **غیرفعال/قابل رزرو نیست** (هاشور بنفش)، گذشته، خارج از ساعات کاری
- رزرو، **تغییر ساعت اتمیک** (لغو قبلی و ثبت جدید در یک تراکنش)، لغو، فهرست رزروها با فیلتر، پروفایل و ویرایش اطلاعات

**مدیر**
- داشبورد با آمار سریع و هشدار «رزرو موجود در محدوده قفل‌شده»
- **مدیریت زمان‌بندی و تعطیلی‌ها**: قفل روز کامل، قفل بازه ساعتی، قفل هفتگی (کل روز یا بازه ساعتی)، پیش‌نمایش محدوده تأثیر پیش از ثبت، انتخاب رفتار با رزروهای موجود (پیش‌فرض: حفظ)، ویرایش، بازکردن با ثبت علت، فعال‌سازی مجدد، جزئیات و تاریخچه کامل هر قفل، فیلتر بر اساس وضعیت، نوع و تاریخ، و نمای ساعت‌به‌ساعت هر روز
- مدیریت رزروها (جست‌وجو، فیلتر تاریخ و وضعیت، لغو با دلیل)
- مدیریت کاربران (جست‌وجو، فعال/غیرفعال‌سازی که کاربر را از همه دستگاه‌ها خارج می‌کند، توضیحات کاربر)
- آمار ماهانه شمسی (نمودار وضعیت جلسات، جنسیت، رزرو روزانه با نمای جدول، ساعت‌های پرتقاضا)
- خروجی Excel راست‌به‌چپ با تاریخ شمسی (کاربران، رزروها، قفل‌ها)
- تنظیم ساعت‌های عمومی قابل رزرو، حداکثر روزهای قابل رزرو در آینده، و تغییر رمز مدیر

## ۵. قوانین رزرو و نحوه تضمین آن‌ها

| قانون | سمت سرور | سمت پایگاه داده |
|---|---|---|
| هر کاربر در هر روز فقط یک رزرو فعال | بررسی در تراکنش | ایندکس یکتای جزئی `(userId, date) WHERE status='ACTIVE'` |
| هر بازه فقط یک رزرو فعال | بررسی در تراکنش | ایندکس یکتای جزئی `(date, hour) WHERE status='ACTIVE'` |
| رزرو هم‌زمان دو کاربر | — | ایندکس یکتا؛ تست با ۱۲ درخواست هم‌زمان: دقیقاً یکی موفق |
| رزرو در زمان گذشته ممنوع | بازه‌ای که شروع شده قابل رزرو نیست | — |
| رزرو در بازه قفل‌شده ممنوع (حتی با API مستقیم) | بررسی همه قفل‌های فعال، شامل قفل‌های هفتگی | — |
| مسابقه بین «ثبت قفل» و «ثبت رزرو» | advisory lock در PostgreSQL: رزروها قفل اشتراکی و تغییر قفل‌ها قفل انحصاری می‌گیرند | — |
| رزرو لغوشده در سوابق می‌ماند | لغو فقط وضعیت را تغییر می‌دهد | CHECK: وضعیت لغو ⇔ زمان لغو |
| قفل هم‌پوشان | یک بازه تا وقتی **هر** قفل فعالی آن را بپوشاند بسته می‌ماند؛ بازکردن یک قفل بقیه را تغییر نمی‌دهد | — |
| قفل‌ها خودکار منقضی نمی‌شوند | فقط مدیر آن‌ها را باز می‌کند | — |
| شکل صحیح هر نوع قفل | اعتبارسنجی Zod | CHECK constraints روی ساعت‌ها و شکل هر نوع |

ساعت پایان قفل **انحصاری** است: قفل ۰۸:۰۰ تا ۱۲:۰۰ بازه‌های ۰۸ تا ۰۹، ۰۹ تا ۱۰، ۱۰ تا ۱۱ و ۱۱ تا ۱۲ را می‌بندد.

## ۶. معماری و ساختار پوشه‌ها

```
prisma/
  schema.prisma            مدل داده
  migrations/              SQL شامل ایندکس‌های جزئی و CHECKها
  seed.ts                  حساب مدیر، تنظیمات و داده نمونه
scripts/db.mjs             اجرای PostgreSQL محلی بدون نصب
src/
  lib/                     کد مشترک کلاینت و سرور (بدون I/O)
    dates.ts  time.ts      تقویم شمسی، کلید تاریخ، زمان تهران
    slots.ts               موتور خالص وضعیت ساعت‌ها و قفل‌ها (منبع واحد قوانین)
    validation.ts          اسکیماهای Zod با پیام فارسی
  server/
    auth/                  OTP، نشست‌ها، ورود مدیر، رمز عبور
    services/              رزرو، قفل، تقویم، کاربران، آمار، خروجی Excel
    db.ts  http.ts  errors.ts  rate-limit.ts  sms.ts  audit.ts
  app/
    (auth)/                ثبت‌نام و ورود
    (user)/                خانه، رزروهای من، پروفایل
    admin/                 ورود مدیر و پنل مدیریت
    api/                   API (هر عملیات با Zod اعتبارسنجی و در سرور مجوزدهی می‌شود)
  components/              اجزای رابط کاربری (ui/ به سبک shadcn/ui)
tests/
  unit/  integration/  e2e/
```

- تاریخ‌ها در همه‌جا به‌صورت «کلید تاریخ» میلادی (`YYYY-MM-DD`) در منطقه زمانی تهران نگهداری و فقط هنگام نمایش به شمسی تبدیل می‌شوند. این کار از خطاهای تبدیل جلوگیری می‌کند.
- قفل هفتگی یک رکورد است و برای همه تاریخ‌های آینده در لحظه محاسبه می‌شود؛ برای هر روز رکورد جداگانه ساخته نمی‌شود.
- هر تغییر مدیریتی (ایجاد، ویرایش، بازکردن و فعال‌سازی قفل؛ لغو رزرو؛ تغییر کاربر و تنظیمات) با مدیر انجام‌دهنده و زمان در جدول `AuditLog` ثبت می‌شود.

## ۷. پیکربندی (متغیرهای محیطی)

| متغیر | توضیح |
|---|---|
| `DATABASE_URL` | آدرس PostgreSQL |
| `DATABASE_URL_TEST` | پایگاه داده جداگانه تست (نامش باید شامل `test` باشد) |
| `AUTH_SECRET` | کلید مخفی هش کدهای OTP؛ حداقل ۳۲ کاراکتر (در production الزامی است) |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_FULL_NAME` | حساب مدیر اولیه. با اجرای دوباره seed رمز عوض **نمی‌شود**، مگر با `ADMIN_RESET_PASSWORD=true` |
| `SMS_PROVIDER` | `console` (فقط توسعه) یا `kavenegar` |
| `KAVENEGAR_API_KEY` / `KAVENEGAR_TEMPLATE` | تنظیمات کاوه‌نگار (متد verify/lookup؛ قالب باید یک توکن داشته باشد) |
| `COOKIE_SECURE` | پشت HTTPS مقدار `true`؛ برای http محلی `false` |

قوانین OTP: کد ۵ رقمی با اعتبار ۲ دقیقه، حداکثر ۵ تلاش برای هر کد، فاصله ۶۰ ثانیه بین ارسال‌ها، حداکثر ۵ کد در ساعت برای هر شماره، به‌علاوه محدودیت بر اساس IP.

## ۹. نکات امنیتی

- کنترل نقش در سمت سرور: هر API و هر صفحه محافظت‌شده نشست را در پایگاه داده بررسی می‌کند. کوکی کاربر (`bk_session`) و کوکی مدیر (`bk_admin`) جدا هستند و هر دو `httpOnly` و `SameSite=Lax` هستند.
- توکن نشست و کد OTP فقط به‌صورت هش ذخیره می‌شوند و مقایسه با زمان ثابت انجام می‌شود.
- درخواست‌های تغییردهنده از مبدأ دیگر رد می‌شوند (CSRF).
- محدودیت نرخ درخواست در PostgreSQL و اتمیک است (برای OTP و ورود مدیر).
- هدرهای امنیتی: `X-Frame-Options`، `X-Content-Type-Options` و `Referrer-Policy`.
- ورود آزمایشی (provider نوع `console`) در production خطا می‌دهد و کدی را نمایش نمی‌دهد.
